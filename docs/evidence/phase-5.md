## Observaciones

- El heartbeat con `last_error` deja una fila en `sync_logs` (`records_processed = 0`, `status = error`, a las 20:03:43 UTC): es el agente reportando que no pudo conectar mientras la API estaba caída. Es lo esperado del contrato y el agente lo deduplica (solo lo repite si cambia el mensaje o pasan 15 min).
- Un `Sender` con la clave rechazada (401) conserva los lotes en la cola y reintenta con el backoff máximo; con 400/413/422 descarta el lote y sigue; con 409 descarta toda la reconciliación y la replanifica. Cubierto por pruebas con una API falsa que imita la idempotencia por `batch_id` (`internal/sender`).
- Decisión de diseño: el diff compara una huella que incluye además categoría y activo; el `sync_hash` que viaja a la API es siempre el del contrato (`sku + precio + stock + nombre`). Sin esto, desactivar un producto en el ERP sin tocar nada más no llegaría nunca a la nube.
- Pendiente de fases futuras (no bloquea el Gate): pedidos hacia el ERP (Fase 7); ejecutar el agente como servicio de Windows; validar el mapeo de Saint contra una base real.
